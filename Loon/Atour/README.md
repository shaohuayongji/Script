# 亚朵签到 · Loon 单订阅插件（R5）

## 更新与订阅

R5 把“获取登录信息、自动签到、手动签到”放回同一个插件，三项功能可在插件页面分别开关。原订阅地址不变，更新后确认描述以 **R5** 开头。

[亚朵签到插件](https://raw.githubusercontent.com/shaohuayongji/Script/master/Loon/Atour/AtourCheckIn.plugin)

Loon 插件参数页应显示：

| 开关 | 初次默认值 | 用途 |
| --- | --- | --- |
| 获取登录信息（临时） | 关闭 | 首次配置或会话失效时临时开启 |
| 自动签到 | 开启 | 每天设备本地时间 08:40 运行 |
| 手动签到 | 开启 | 提供“亚朵签到（手动）”运行入口 |

采用官方 `[Argument] switch` 和 `enable={参数名}`，需要 Loon Build 733 或以上。开关默认值针对首次加载参数；更新可能保留用户已有设置，请确认实际开关状态。依据：[Loon 官方插件参数文档](https://nsloon.app/docs/Plugin/#argument)。

## 如何使用

1. 在 Loon 更新原“亚朵签到”订阅，确认 R5。打开插件详情中的参数/设置页面，分别选择三项开关。日常保持获取关闭，自动和手动开启；只想手动测试时也可以关闭自动签到。
2. 停用此前单独添加的“亚朵获取登录信息”插件及旧版、重复规则，只保留这一份订阅。
3. 已有 R3/R4 保存的登录信息可以继续用，无需重新获取。手动入口在 Loon 的脚本列表中，点击“亚朵签到（手动）”的运行按钮。
4. 首次获取或登录失效时，临时打开“获取登录信息（临时）”；开启脚本与 MitM，安装并信任 Loon 生成的证书，连接 Loon，打开已登录的亚朵 App“签到集拼图”页面。
5. 收到“候选登录信息已保存 · R5”后，回插件参数页**关闭获取开关**，保留整个签到插件开启。随后手动运行一次，服务器状态查询验证候选信息后才替换旧会话。

获取只是保存请求中的候选凭据，不代表登录有效或签到成功。候选保存到独立本地键，查询失败保留旧会话并停止本次运行，不会转用旧账号提交签到。当天已签到只查询，未签到时仅尝试一次普通提交，再查询确认；服务要求验证码时去 App 正常完成。

## App 页面兼容性

用户 R3 对照截图显示旧响应拦截插件会影响签到页面加载，具体机制未定位。R4 拆分获取与日常运行；R5 按用户需求恢复单订阅，但只使用独立的轻量**请求**获取脚本，`requires-body=false`，不读取 App 响应或请求正文、不初始化密码库、不发额外网络请求。获取开关默认关闭，脚本还有开关参数检查，即使被触发也会在关闭或参数异常时原样放行，不保存信息。

**脚本开关不等同于 MitM 域名开关。** 合并版声明 `miniapp.yaduo.com`，关闭获取开关不会移除该声明；当全局 MitM 开启时，该域名仍可能解密。官方文档明确了脚本 `enable` 的参数用法，本次未找到可用同一布尔参数同步控制 MitM 域名的可靠依据，未写入未经确认的配置。如果合并版在获取关闭时仍造成 App 页面异常，请暂时关闭整个插件并反馈，这仍需手机实测。无需修改其他插件的 MitM 域名或全局配置。
