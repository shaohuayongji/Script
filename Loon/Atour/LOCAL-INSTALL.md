# 亚朵签到：Loon 版

已按亚朵当前官方 App 内会员 H5 的接口重新编写，选用 **亚朵 App 的“签到集拼图”入口** 获取登录信息。脚本支持今日状态查询、已签跳过、一次普通签到、签到后复查，以及官方公开客户端使用的 SM2/AES 响应解密。仅使用最近一次保存的账号，不进行抽奖、兑换或其他任务。

**当前官方页面点击签到时包含极验验证流程，因此不能保证每天无人值守签到。** 服务允许普通请求时，脚本可以执行签到；服务要求验证码时会停止并提醒你去 App 完成。它不会伪造验证结果、重放一次性验证码头或自动生成同盾动态签名。

## R2 更新（2026-10-04）

修正成功响应带有 `At-Client-Sign` 时整份会话被拒绝保存的问题。签名头仍会移除；保存登录信息不代表服务一定接受普通请求，运行时必须先通过服务器状态查询。其他签名/时效查询参数仍会停止获取，但现在通知会列出字段名，不输出参数值。增加独立的 **亚朵签到（手动）** 入口。

## 先安装，再用自己的账号验证

1. 将 `atour.loon.js` 传到 iPhone，在 Loon 的脚本编辑功能中创建或导入同名本地脚本，也可新建后粘贴全部内容。文件已内置依赖，无需 Node.js、青龙、npm 或额外远程库。
2. 把 `loon-snippet.conf` 的三条规则合并到正在使用的配置的 `[Script]` 区段，将 `miniapp.yaduo.com` 追加到现有 `[MITM]` 的 `hostname` 列表。**片段不是完整配置，不要替换整份配置。** 已熟悉本地插件导入的，也可使用 `AtourCheckIn.local.plugin`；两种方法选一种，避免重复运行。
3. 开启 Loon 脚本/重写和 MitM，安装并信任 Loon 自己生成的 MitM 证书，启动 Loon 连接。建议使用支持 `auto-redirect`、`auto-cookie` 选项的新版 Loon。
4. 打开并登录亚朵 App，进入会员签到页“签到集拼图”。页面查询成功后应出现 **“亚朵签到 · 登录信息已保存”**。如果没有，可退出该页面再进入；仍未获取时，按 App 的正常流程手动签到一次，成功的签到响应也能保存登录信息。
5. 在 Loon 的脚本列表中找到 **“亚朵签到（手动）”**，使用运行按钮执行。看到“今日已签到”表示服务器查询确认；“签到成功”表示提交后已复查确认。首次获取时如果当天已手动签到，只能验证查询路径；应在次日未签到时运行一次，才能验证你的账号是否允许普通自动签到。
6. 保持 Loon 运行和设备联网。定时规则为 `40 8 * * *`，每天设备本地时间 **08:40**；上海时区下是北京时间 08:40。定时执行由 Loon 调度。

如果 App 请求无法被 Loon 的 MitM 解密，本方法不能捕获会话；先确认脚本名、规则、证书和域名设置。微信小程序只有在实际请求同样的接口、参数和响应格式时才适用；本次核查有明确证据的是 App 内 H5，因此优先用 App。

## 通知的含义

| 通知 | 含义与处理 |
| --- | --- |
| 登录信息已保存 | 本机捕获了成功响应对应的会话；手动运行测试 |
| 今日已签到 | 状态接口确认今日已完成，未再次提交 |
| 签到成功 | 签到返回成功，且再次查询确认今日完成 |
| 需要人工验证 | 服务要求验证码；打开 App 正常验证并签到，脚本不重试 |
| 需要重新登录 | 登录失效或访问受限；在 App 登录并重新打开签到页获取信息 |
| 登录信息已保存，待验证 · R2 | 已去除 `At-Client-Sign`，保留登录信息；运行手动脚本，确认服务器接受普通查询 |
| 普通查询未通过 · R2 | 普通状态查询被服务拒绝，未提交签到；可能需要动态签名适配，按通知中的业务码排查 |
| 需要参数适配 · R2 | 查询字符串含可疑签名/时效/验证字段，未覆盖已有会话；通知只显示字段名，可用于排查 |
| 签到结果待确认 | 请求超时、响应异常或后续状态未确认；去 App 核对。脚本不会自动再次提交 |
| 解密失败、未知加密、数据结构变化 | 响应协议可能变化或请求被拦截；保留旧会话，需要排查适配，不能当作签到成功 |
| 业务码 `10003` 等其他错误 | 服务业务错误；不能仅凭该码断定登录失效，需结合 App 状态核查 |

`100042` 按官方客户端解释为需要验证，`10002` 为登录问题。脚本不自动刷新登录 token；失效后重新执行获取步骤。捕获规则原样放行请求与响应，不修改正常 App 操作。每次定时运行均向服务器查询今日状态，本地日期记录不会代替查询。

登录 token、Cookie 与必要的设备头只保存在 Loon 本机的 `atour_loon_session_v1` 中，只发送到亚朵对应接口。它们不会出现在脚本日志和通知里；不要把完整请求、存储内容或带凭据的配置发到聊天、截图或公开仓库。排查时只提供通知文字、HTTP 状态或业务码即可。

## 失败时如何提供日志

在 Loon 找到 **亚朵签到（手动）**，执行后打开该脚本的运行日志，复制从 `start mode=checkin` 到 `finish mode=checkin` 的内容。获取登录信息时出错，则提供 **亚朵获取登录信息** 中从 `start mode=capture` 到 `finish mode=capture` 的日志。不同 Loon 版本的入口位置可能不同，以脚本详情里的日志/运行记录入口为准。

每一行包含脚本版本和本次运行编号，记录获取/查询/签到阶段、HTTP 状态、业务码、加密类型，以及服务返回的今日签到状态。可疑查询字段仅记录已知字段名。不会记录请求 URL、Token、Cookie、签名值、验证码值、账号资料、响应正文或原始网络错误。

例如下面是**模拟的验证码失败日志**，不是实际账号结果：

```text
[ATOUR 2026.10.04.2 abc123] start mode=checkin
[ATOUR 2026.10.04.2 abc123] request.response endpoint=indexInfoV2 HTTP=200 encryption=none
[ATOUR 2026.10.04.2 abc123] request.decode endpoint=indexInfoV2 retcode=0
[ATOUR 2026.10.04.2 abc123] state.before todaySigned=false
[ATOUR 2026.10.04.2 abc123] request.decode endpoint=signIn retcode=100042
[ATOUR 2026.10.04.2 abc123] finish mode=checkin
```

这些脚本日志可用于反馈。请不要开启全量 HTTP 抓包后发送完整请求，也不要发送 Loon 本地存储内容。

核查日期 **2026-10-04**。找到的原作者 [Sliverkiss Gist](https://gist.github.com/Sliverkiss/2e2093bfd5f524d58c8e90fed9beacfd) 最近修订为 **2023-11-23**；[jivei/Surge 镜像](https://github.com/jivei/Surge/blob/main/js/atour.js) 的该文件提交停在 **2023-09-16**。旧教程引用的原始脚本下载路径已返回 HTTP 404。未找到足以证明这些旧脚本目前真实签到成功的近期记录。

这些证据能确认维护和下载问题，不能单凭年份断言业务接口失效。亚朵 [当前公开会员页面](https://wechat.yaduo.com/hy/) 引用的 `20260917191702` 构建仍使用 `GET /atourlife/signIn/indexInfoV2` 和 `GET /atourlife/signIn/signIn`，但点击签到包含极验验证，客户端还支持加密响应。新脚本因此采用当前请求方式、过滤一次性字段、支持解密，并增加提交前后状态确认。
